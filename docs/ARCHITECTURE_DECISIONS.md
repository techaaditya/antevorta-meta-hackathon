# Architecture Decision Records (ADRs)

These decisions are the source of truth for the hackathon code. Reopen them only when a concrete test or blocker justifies it.

## ADR-001 — Product center: Decision Stress Test

**Decision:** Ship a Personal Decision Workbench framed as an AI Decision Stress Test.

**Rationale:** Preserves the research-backed premise from the master documents while making the demo concrete: a model-selected tool call, deterministic constraint report, assumption edit, and revised outcome.

**Rejected:** Pure Future-Self chatbot, long-horizon life simulator, “personality twin,” single generic chat screen.

## ADR-002 — Competition track

**Decision:** Build for Your World.

**Rationale:** Adult students and early-career professionals facing education/research/work trade-offs are a domain we understand firsthand.

## ADR-003 — Model and API

**Decision:** Use the official Meta Model API, base URL `https://api.meta.ai/v1`, and configure `MODEL_API_KEY` only on the backend. Default model ID `muse-spark-1.3`; model ID remains environment-configurable.

**Rationale:** Official docs currently recommend Muse Spark 1.3 for new agentic work and document tool calling through the OpenAI-compatible SDK interface. Re-verify account access before release.

## ADR-004 — Agent topology

**Decision:** One bounded tool-calling orchestrator plus deterministic validation. Optional separate critic call is a stretch task.

**Rationale:** A genuine model-selected tool loop gives meaningful autonomy without the failure surface and token cost of multiple uncoordinated agents. A deterministic verifier is easier to audit than a second model that merely agrees with the first.

## ADR-005 — Reasoner isolation

**Decision:** The constraint engine is pure deterministic Python. The LLM never computes or overwrites time/money arithmetic.

**Rationale:** Judges can verify calculations; missing inputs remain unknown.

## ADR-006 — Data persistence

**Decision:** No server-side database for the first competition vertical slice. The API is stateless; the user can export the report locally. PostgreSQL/event sourcing from the long-range product blueprint is retained as a post-hackathon design, not a critical path.

**Rationale:** Reduces collection of sensitive decision data and removes auth/ownership/deletion risk in the limited build window. If persistent accounts/history become essential, add PostgreSQL only together with auth, consent, ownership tests, and deletion/export controls.

## ADR-007 — No life probabilities

**Decision:** No invented individual success probability, stress score, burnout prediction, or unsourced population rate.

**Rationale:** The product offers conditional scenario narratives, not an oracle. The only numeric values in the initial report are user inputs and deterministic calculations.

## ADR-008 — Provider fallback

**Decision:** When API key is missing or provider call fails, return explicitly labelled deterministic fallback. Never represent fallback text as generated by Muse Spark.

## ADR-009 — External research

**Decision:** Do not allow arbitrary browsing claims in v1. Add research grounding only if citations, retrieval timestamps, source URLs, and error behavior can be verified end-to-end. If no verified source is present, state that no verified reference-class rate was found.

## ADR-010 — Security boundary

**Decision:** Agent tools are read-only and allow-listed. No model-created shell commands, external writes, third-party messaging, or unconfirmed calendar actions. API key stays on the server.

## ADR-011 — Demo integrity

**Decision:** Label synthetic demo data as synthetic; identify what was built during the hackathon in Git commits and the submission. Do not imply the supplied master documents are completed product code.

## ADR-012 — Naming

**Decision:** Use Antevorta as a working codename. Do not claim trademark/domain clearance.
